# Migration Tool

Zero-downtime PostgreSQL migration tool using logical replication.

## How it works

`migrate.sh` orchestrates a migration in steps: preflight checks, schema copy, data dump-and-restore (with snapshot-based consistency), live replication via PostgreSQL logical subscriptions, and cutover with sequence sync.

### Subcommands

`migrate.sh <subcommand>` — requires `SRC` and `TGT` env vars (PostgreSQL connection strings).

- `preflight` — check versions, tools, wal_level, connectivity
- `copy-schema` — dump schema from source, apply pre-data to target
- `verify-schema` — compare tables, columns, indexes, sequences, FKs between source and target
- `dump-and-restore` — create pub+slot, snapshot dump, restore data+indexes, start subscription
- `monitor` — watch replication lag
- `verify` — compare row counts, checksums, sequence values
- `cutover` — sync sequences, tear down replication
- `cleanup` — abort/reset a failed migration (drop subscription, publication, slot)

### Key env vars

| Variable | Default | Purpose |
|---|---|---|
| `SRC` | (required) | Source PostgreSQL connection string |
| `TGT` | (required) | Target PostgreSQL connection string |
| `MIGRATE_SRC_PROXY` | `$SRC` | Connection string TGT uses to reach SRC (for subscriptions) |
| `MIGRATE_SLOT` | `migration_sub` | Replication slot/subscription name |
| `MIGRATE_PUB` | `migration_pub` | Publication name |
| `MIGRATE_JOBS` | `4` | Parallelism for pg_dump/pg_restore |
| `MIGRATE_WORK_DIR` | `.` | Directory for schema/data dumps |

## Testing

All test commands require `SRC` and `TGT` env vars and run from the `test/` directory.

```bash
# Functional tests (~6 min) — runs on every PR via GitHub Actions
SRC=postgresql://... TGT=postgresql://... make -C test test

# Integration test (~2 hours, needs seed data loaded first)
SRC=postgresql://... TGT=postgresql://... make -C test long-test

# Both suites
SRC=postgresql://... TGT=postgresql://... make -C test test-full

# Load seed data into source (interactive confirmation)
SRC=postgresql://... make -C test load_data
```

### Functional tests (`test/test_functional.py`)

Five independent test classes, each creates its own tiny schema:

- **TestQuotedTableNames** — quoted/reserved-word table names (`"User"`, `"Order"`, `"Group"`)
- **TestSequences** — GENERATED ALWAYS, GENERATED BY DEFAULT, standalone sequences
- **TestForeignKeys** — multi-level FK chain, verifies constraints are enforced on target
- **TestIndexes** — btree, GIN (jsonb, array), unique constraint indexes
- **TestProxy** — migration through a socat proxy (skipped if TGT is remote)

### Integration test (`test/test_migration.py`)

Full end-to-end migration with 10GB seed data. Requires `make -C test load_data` first.

## CI

GitHub Actions workflow (`.github/workflows/test.yml`) runs functional tests on every push to `main` and on PRs. Uses two Postgres 18 service containers with `wal_level=logical` enabled on source.
